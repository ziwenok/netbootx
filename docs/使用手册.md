# NetBootX 使用手册

面向第一次使用的人。按顺序照做即可。

---

## 一、这是什么

一台 PXE 服务器。把操作系统的 ISO 文件放进去，别的电脑通过网络启动就能装系统。

想象你有 10 台新服务器要装系统。传统做法是做一个 U 盘，一台台插上去装，一天没了。
用 NetBootX，10 台同时开机按网络启动，选菜单，全部同时开始装。

## 二、五分钟跑起来

### 第 1 步：下载引导文件

```bash
cd netbootx
./scripts/fetch-boot.sh
```

这一步下载 iPXE（客户机 PXE 启动后实际运行的程序）。大约 4MB，只需做一次。

看到 8 个绿色 ✅ 就成功了。

### 第 2 步：编译

```bash
make build
```

产物是 `bin/netbootx`，约 10MB 的单个可执行文件，没有任何运行时依赖。

### 第 3 步：放 ISO

```bash
cp ~/Downloads/ubuntu-24.04.2-desktop-amd64.iso iso/
```

**不需要**解压、不需要挂载、不需要改名。文件名里有中文/空格也能用（但建议避免）。

ISO 可以放子目录，也可以软链接：

```bash
mkdir -p iso/linux iso/windows
ln -s /Volumes/Data/isos/win11.iso iso/windows/win11.iso
```

### 第 4 步：启动服务

```bash
sudo ./bin/netbootx
```

为什么要 sudo？因为 DHCP 用 67 端口、TFTP 用 69 端口，都是特权端口。

看到这样的输出就成功了：

```
  ╔══════════════════════════════════════════════════════╗
  ║   NetBootX v1.0.0                                    ║
  ║   增强版 PXE / UEFI HTTPBoot 服务器                   ║
  ╚══════════════════════════════════════════════════════╝
   根目录   /Users/you/netbootx
   本机 IP  192.168.1.100
   DHCP 模式 proxy（局域已有 DHCP，本机只做 PXE）

  🌐 管理界面: http://127.0.0.1:16080
  💡 把 ISO 文件放进: /Users/you/netbootx/iso
```

浏览器会自动打开管理界面。

### 第 5 步：在界面上点开始

1. **本机 IP**：下拉选一个 IP。选哪个？选**和你要装系统的机器在同一个网段**的那个。
   不确定就选不是 127.0.0.1 的那个。
2. **DHCP 模式**：
   - 家里/公司有路由器在发 IP → 选 **proxy**
   - 这是个隔离的测试网，没有别的 DHCP → 选 **full**，然后填地址池
3. 点绿色的 **▶ 开始**

启动成功后，界面右上角会变绿，显示「运行中」。

### 第 6 步：客户机启动

在要装系统的机器上：

1. 开机，看到厂商 logo 时狂按 `F12`（Dell）/ `F11`（部分）/ `Esc`（HP）/ `F8`（ASUS）
   不确定就都试一遍，或者进 BIOS 找 Boot Menu
2. 选 **Network Boot** / **PXE Boot** / **LAN**
3. 屏幕上会依次出现：
   ```
   >>Start PXE over IPv4
   ...
   NetBootX 启动菜单
   ─────────────────────────
   1. Ubuntu 24.04.2 LTS   (4.7 GB)
   2. Windows 11           (5.4 GB)
   ─────────────────────────
   请选择（30 秒后自动启动第 1 项）：
   ```
4. 选你要装的系统，回车

搞定。

## 四、DHCP 模式详解（最容易踩坑的地方）

### proxy 模式（默认，推荐）

**什么时候用**：局域网里已经有一个 DHCP 服务器（路由器、公司网络、云环境）。

**原理**：NetBootX 不分配 IP，只在旁边听。当它听到客户机发出 PXE 请求时，
额外回一个「PXE 信息包」，告诉客户机「引导文件去这个服务器拿」。
客户机的 IP 还是由原来的 DHCP 服务器分配。

**优点**：完全不影响现有网络，插上就能用，拔掉就走。

**要求**：现有 DHCP 服务器必须支持 PXE（几乎所有家用路由器和企业 DHCP 都支持）。

### full 模式

**什么时候用**：隔离的测试网络，或者这个网段根本没有 DHCP。

**原理**：NetBootX 就是唯一的 DHCP 服务器，负责分配 IP + 告诉客户机去哪引导。

**注意**：如果这个网段还有另一个 DHCP 服务器，两个会打架，
客户机可能拿到错网关导致上不了网。**确认没有别的 DHCP 再用。**

### external 模式

**什么时候用**：你有企业级 DHCP（Windows Server DHCP、ISC DHCP），
并且**有权限改它的配置**。

**原理**：NetBootX 完全不碰 DHCP，只提供 TFTP 和 HTTP。
你需要在 DHCP 服务器上手动配置：

```
next-server = <NetBootX 的 IP>
filename    = x86_64/ipxe.efi    (UEFI 客户机)
filename    = bios/undionly.kpxe (BIOS 客户机)
```

Windows Server DHCP 的话，在「作用域选项」里配 066 (Boot Server Host Name)
和 067 (Bootfile Name)。

## 五、支持的 ISO 与识别逻辑

NetBootX **不看文件名**，它打开 ISO 读里面的文件结构来判断这是什么系统。
所以你把 `ubuntu.iso` 改名成 `abc.iso` 也照样能识别。

识别顺序：

1. 找 `sources/boot.wim` → Windows 系列
   - 有 `sources/install.wim` → Windows 安装盘
   - 没有 → WinPE
2. 找 `casper/vmlinuz` → Ubuntu
3. 找 `live/vmlinuz` → Debian Live
4. 找 `images/pxeboot/vmlinuz` → RHEL / Fedora / Rocky / Alma
5. 找 `isolinux/vmlinuz` → CentOS 系 / openEuler / Kylin
6. 找 `boot/x86_64/loader/linux` → SUSE
7. 找 `arch/boot/x86_64/vmlinuz` → Arch
8. 找 `boot/vmlinuz-lts` → Alpine
9. 找 `vmxboot/efi/bootx64.efi` → VMware ESXi
10. 找 `boot/loader` → FreeBSD
11. 都不匹配 → 标记「未知」，但仍然尝试通用方式启动

## 六、故障排查

### 客户机没有任何反应，直接跳过了网络启动

1. 客户机 BIOS 里没开 PXE：进 BIOS，找 `Network Stack` / `PXE Boot` / `Legacy Boot`，
   打开它
2. 网线没插：PXE 必须走有线网（无线网卡基本都不支持 PXE）
3. 交换机没通：确认客户机和服务端在同一个二层网络（VLAN 相同）

### 卡在 `DHCP...` 不动

```bash
# 服务端确认 DHCP 在跑
sudo lsof -iUDP:67
```

- 没输出 → 服务没启动，或者用错了模式
- 有输出但客户机还是拿不到 → 防火墙挡了，检查：
  ```bash
  # macOS
  sudo /usr/libexec/ApplicationFirewall/socketfilterfw --listapps
  # Linux
  sudo ufw status
  ```

### 卡在 `TFTP...` / `TFTP timeout`

1. 确认 `boot/` 目录文件齐全：`./scripts/verify.sh`
2. 确认 69/UDP 没被别的 TFTP 服务占用：`sudo lsof -iUDP:69`
3. 如果是跨网段，TFTP 需要能路由到（TFTP 用随机端口回包，NAT 会挡）

### 出现菜单但选了之后黑屏

1. 看服务端日志，是不是 HTTP 请求 404 了
2. 点界面上该 ISO 的「预览」，看看生成的脚本里 kernel 路径对不对
3. 有些 ISO（比如某些 Windows 版本）需要额外的驱动，
   或者 UEFI 模式启动 Windows 会花屏（已知问题，可以试 Legacy BIOS 模式）

### Secure Boot 报错 `Security Violation`

1. 客户机 BIOS 里关掉 Secure Boot（临时方案）
2. 或者用签名过的 iPXE + shim（需要额外配置）

### 端口被占用

```bash
# 看谁占了
sudo lsof -i :67 -i :69 -i :16000 -i :16080
```

如果是 iVentoy 占着，先停掉它。两者不能同时跑（DHCP 端口冲突）。

## 七、命令行参数

```
./bin/netbootx -h
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `-ip` | 本机对外 IP | 自动探测 |
| `-iface` | 绑定网卡名 | 自动 |
| `-mode` | DHCP 模式 full/proxy/external | proxy |
| `-range-start` | 地址池起始 | 192.168.123.200 |
| `-range-end` | 地址池结束 | 192.168.123.250 |
| `-web` | Web 端口 | 16080 |
| `-http` | HTTP 端口 | 16000 |
| `-tftp` | TFTP 端口 | 69 |
| `-dhcp` | DHCP 端口 | 67 |
| `-autostart` | 启动即开 PXE 服务 | false |
| `-no-browser` | 不自动开浏览器 | false |
| `-root` | 软件根目录 | 自动 |

例子：

```bash
# 无界面服务器上跑，指定网卡
sudo ./bin/netbootx -iface en0 -autostart -no-browser

# 用高位端口调试（不需要 sudo，但客户机连不上）
./bin/netbootx -dhcp 16767 -tftp 16969 -http 16000 -web 16080
```

## 八、开机自启

### Linux (systemd)

```bash
./scripts/install.sh    # 会生成 netbootx.service
sudo cp netbootx.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now netbootx
sudo systemctl status netbootx
```

### macOS (launchd)

macOS 上绑定 67/69 需要 root，所以要用 LaunchDaemon 而不是 LaunchAgent：

```bash
./scripts/install.sh
sudo cp com.netbootx.server.plist /Library/LaunchDaemons/
sudo launchctl load /Library/LaunchDaemons/com.netbootx.server.plist
```

## 十、进阶：无人值守安装

装系统最烦的是要守在旁边一路点「下一步」。无人值守就是让安装程序自己走完。

### 原理

安装程序（Anaconda / debian-installer / Windows Setup）都支持「从一个 URL 读配置文件」。
NetBootX 把配置文件放在 `user/autoinstall/` 下，通过 HTTP 暴露出去，
启动时把 URL 塞进内核参数，安装程序自己去拉。

```
客户机启动 → 内核参数带 inst.ks=http://192.168.123.10:16000/user/autoinstall/rocky9-ks.cfg
           → 安装程序拉这个文件 → 按文件里的指示自动装完 → 重启
```

### 支持的类型

| 发行版 | 配置类型 | 内核参数 | 模板文件 |
|---|---|---|---|
| RHEL / CentOS / Rocky / Alma / openEuler / Kylin | Kickstart | `inst.ks=` | `example-kickstart.cfg` |
| Debian / 旧版 Ubuntu | Preseed | `preseed/url=` | `example-preseed.cfg` |
| Ubuntu 20.04+ | Autoinstall (cloud-init) | `autoinstall ds=nocloud-net;s=` | `example-autoinstall.yaml` |
| SUSE / openSUSE | AutoYaST | `autoyast=` | （按 SUSE 文档写 XML） |
| Windows | AutoUnattend.xml | 无需参数，放对位置即可 | `example-AutoUnattend.xml` |

### 怎么用

1. 打开 `user/autoinstall/`，里面有 4 个示例文件，挑对应的复制一份改名：

   ```bash
   cp user/autoinstall/example-kickstart.cfg user/autoinstall/my-rocky9.cfg
   ```

2. 改里面的内容。**必须改的**：
   - `rootpw` / `password`：密码哈希（别用示例里的）
   - `network --hostname`：主机名
   - 分区方案（示例会**清空整块盘**，务必确认）
   - `ssh` 公钥（如果要用密钥登录）

   生成密码哈希：
   ```bash
   # Linux
   python3 -c "import crypt; print(crypt.crypt('你的密码', crypt.mksalt(crypt.METHOD_SHA512)))"
   # 或
   openssl passwd -6 '你的密码'
   ```

3. 在 NetBootX 界面上，给对应 ISO 挂上这个模板。

4. 客户机 PXE 启动，选这个 ISO，剩下的不用管。

### 各发行版的具体说明

#### RHEL 系（Kickstart）

```
# 关键行
inst.ks=http://192.168.123.10:16000/user/autoinstall/my-rocky9.cfg

# 安装源（NetBootX 会自动带上）
inst.stage2=http://192.168.123.10:16000/iso/{id}/
```

模板里必须有 `%packages ... %end` 段，否则会装成最小系统。

#### Debian 系（Preseed）

```
preseed/url=http://192.168.123.10:16000/user/autoinstall/my-preseed.cfg
```

注意：**Ubuntu 20.04 之后不用 preseed 了**，改用 autoinstall。
如果你拿 preseed 去装 Ubuntu 22.04，会卡在分区界面。

#### Ubuntu 20.04+（Autoinstall）

```
autoinstall ds=nocloud-net;s=http://192.168.123.10:16000/user/autoinstall/
```

注意 URL 结尾的 `/` 和 `ds=nocloud-net;s=` 的写法，少一个字符都不行。

cloud-init 会去拉 `user-data` 和 `meta-data` 两个文件。
如果你只放了一个 `xxx.yaml`，需要在 NetBootX 里做路径映射（见下）。

#### Windows（AutoUnattend）

Windows 的无人值守是**从 WinPE 里读文件**，不是从网络拉。
所以 NetBootX 的做法是：把 `AutoUnattend.xml` 作为额外的 initrd 塞进 wimboot，
让它出现在 WinPE 的 `X:\` 根目录，Windows Setup 启动时会自动找它。

```
kernel wimboot
initrd --name bootmgr   ${base}/iso/{id}/bootmgr
initrd --name bcd       ${base}/iso/{id}/boot/bcd
initrd --name boot.sdi  ${base}/iso/{id}/boot/boot.sdi
initrd --name boot.wim  ${base}/iso/{id}/sources/boot.wim
initrd --name AutoUnattend.xml ${base}/user/autoinstall/my-AutoUnattend.xml
boot
```

注意最后一行：多塞一个 `initrd --name`，wimboot 会把它放到 WinPE 根目录。

### 验证模板有没有生效

**方法 1：看界面日志**

客户机启动后，日志里会出现：
```
[http] GET /user/autoinstall/my-rocky9.cfg 200
```
有这个说明安装程序真的来拉了。没有的话说明内核参数没带上。

**方法 2：手动 curl**

```bash
curl -v 'http://192.168.123.10:16000/user/autoinstall/my-rocky9.cfg'
```

**方法 3：看客户机屏幕**

安装程序启动后第一屏会显示内核命令行，检查有没有 `inst.ks=...`。
如果没有，按 `Tab` 或 `e` 编辑引导项，手动加上去试试。

### 常见问题

**Q: 装完重启又进了安装程序？**
A: Kickstart 模板最后要有 `reboot`，并且客户机 BIOS 里把硬盘调到网络启动前面。
   或者用 `reboot --eject`。

**Q: 报错 `Unable to retrieve inst.ks`？**
A: 检查：① 文件真的在 `user/autoinstall/` 下 ② 文件名大小写 ③ 服务端 HTTP 端口对不对
   ④ 客户机能不能访问到服务端 IP。

**Q: Ubuntu autoinstall 卡在 `subiquity` 界面？**
A: 内核参数写错了。正确写法是 `autoinstall ds=nocloud-net;s=http://IP:PORT/user/autoinstall/`
   注意 `nocloud-net` 后面是 `;s=` 不是 `;u=`。

**Q: 分区会清空硬盘吗？**
A: 示例模板都是**清空第一块盘**。生产环境务必改成分区方案，或者在测试机上先试。

## 十一、性能调优

### 同时装很多台机器

NetBootX 本身是 Go 写的，单机能轻松扛几十台同时 PXE 启动。瓶颈通常在：

| 瓶颈 | 表现 | 解决 |
|---|---|---|
| 磁盘 IO | 多台同时拉 ISO 时变慢 | ISO 放 SSD；或 `os.PageCache` 自动缓存热点数据 |
| 网卡带宽 | 千兆网 20 台同时装会卡 | 换万兆；或分批装 |
| TFTP 慢 | 引导文件下载慢 | 引导文件才 1MB，不影响；主要是内核走 HTTP |

**关键**：内核和 initrd 走 HTTP（不是 TFTP），HTTP 是流式的，不会因为多台并发而排队。

### 大 ISO（>4GB）

Windows 的 `install.wim` 经常超过 4GB。NetBootX 支持 ISO9660 的多段文件
（Multi-Extent，flags 0x80），能正确读出来。已验证。

### 缓存

NetBootX 会把打开过的 ISO 目录树缓存在内存里，按 mtime 失效。
同一张 ISO 被 20 台机器同时读，只会解析一次目录结构。
